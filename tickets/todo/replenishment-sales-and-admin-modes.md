# Sales and administration modes for replenishment

Captured: 2026-11-05

Related: `tickets/todo/replenishment-suppliers-and-sharing.md`

## Goal

Use one `ReplenishmentPanel` that adapts to the application's existing administration mode: a fast, supplier-tool-free counter flow for sales staff and a wide, supplier-oriented list for administration. Implement after the supplier ticket's round-six truncation and status/supplier menu work, on the same code without undoing it.

## Context and decisions

- On the user's MacBook at roughly 1000 pt, the current half-width detail panel squeezes the list, wraps status tabs and product names, and shows supplier/export tools at the counter. Administration hides the supplier rail below 1200 px while leaving too much space for the right panel.
- Read `AppUser`'s `administrationMode` (set by `JRootApp.openAppView`) in `activate()`; add `isAdministrationMode()` if needed. Rebuild the layout if the mode changes. No switch inside this screen.
- **Sales (`administrationMode = false`):** hide the supplier rail and combo, supplier table column, selection checkboxes and multiselect, Export, Manage suppliers, Order panel and send dialog. Clicking a row opens its detail; Escape or closing the detail returns to a new-request form. Keep the right panel visible at 340–380 px. With no selection, focus the scan field in the new-request form; saving clears the form, restores scan focus and leaves the new row visible. On entering from sales, focus the search field so a cashier can find a request immediately. With one row, show the branded next-step action; the supplier is read-only, while customer and note remain editable. Columns are Request | Customer | Status (only in All) | Added. Search also finds customer names. Sales mode must not permit supplier assignment, sending or management even if the user's role grants those permissions.
- **Administration (`administrationMode = true`):** show the 200–232 px supplier rail at widths of at least 980 px; show the combo only below 980 px. With nothing selected the list uses all available width and the detail panel is absent. One selected row opens Detail; two or more open Selection/Assign to. Creating a new request temporarily opens the form in the right panel. The right panel is always 340–380 px wide, never proportional; remove the draggable divider or give the list the extra space (`resizeWeight = 1`) and remember a user-adjusted detail width if dragging remains. Remove Order as a right-panel mode. Put a primary “Send order (N)” beside Edit supplier in the supplier header, opening the existing send dialog and preview; when the supplier has no WhatsApp, default to Text file and retain the existing warning. Below roughly 720 px of useful list width, render Supplier and Customer as a secondary caption under the product name (omit Supplier when already viewing that supplier), keeping Added as a compact column.
- **Both modes:** status segments stay on one row. When translations cannot fit, use short localized labels (e.g. “Pend. 29”) or horizontally scroll the segmented control, never wrap. Show the mono reference above a product name of at most two lines with ellipsis and a full-name tooltip. Preserve round-six scale-aware touch heights and content-derived widths.
- Inspect `RolePermissions` and `V25__seller_replenishment_permissions` so seller access to the screen survives the mode change; the mode still gates supplier operations in the panel. Validate English, Spanish and Catalan, light and dark themes.

## Done when

- In sales mode, a cashier creates a customer order, finds it by customer name and marks it delivered without seeing or invoking supplier tools.
- In administration at 1000–1280 px, the supplier rail is visible and the list spans all remaining width until a row is selected; the right panel never exceeds 380 px.
- Status tabs never wrap and no button label clips in CA/ES/EN. Product names occupy at most two lines, with tooltip access to the full name.
- `./gradlew spotlessApply` and layout tests pass for each mode: sales has no rail, supplier combo or Supplier column and has a visible right panel; administration has a rail at 1000 px, no right panel without selection and a right panel at most 380 px when selected.
- New `sales-*` and `admin-*` screenshots cover CA/ES/EN, light/dark, 1000/1280/1470 px, plus the sales new → find → deliver flow. Manually verify administration on the MacBook Air and sales on the POS, including keyboard/focus and translated labels; record actual results here before closing.

## Implementation and verification (2026-11-05)

- `AppUser.isAdministrationMode()` exposes the mode set by `JRootApp.openAppView`; `ReplenishmentPanel.activate()` updates the existing panel's layout and selection mode when the mode changes. Reviewed `RolePermissions` (replenishment is in the maintenance catalogue) and the already committed `V25__seller_replenishment_permissions` (seller screen/add permissions); neither required an edit. Sales actions that assign, manage or send are also guarded in the panel.
- Sales hides all supplier and export controls, keeps a 360px right dock and single-row horizontally scrollable status tabs; Escape and the accessible Close action clear the selected detail. New requests return to a blank scan form and a visible row. Existing customer-name filtering is in `DataLogicReplenishment.list`. Administration shows a 232px rail from 980px (combo below), uses the full list width until selection or creation, and shows the same 360px dock only for detail/selection/creation. The Order card is removed; Send order (N) in the supplier header opens the existing dialog. A supplier without WhatsApp defaults to Text file and still shows the missing-phone reason. Narrow admin lists place supplier/customer in the product caption; the request reference remains above at most two ellipsized name lines with full-name tooltip.
